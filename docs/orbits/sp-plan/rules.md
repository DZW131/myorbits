# sp-plan Rules

## Objective
Produce an execution plan from an approved design.

## Must Do
- Plan before coding.
- Split work into concrete task slices.
- Name target files or areas.
- Define verification for each task.
- Record risks and open questions.

## Must Not Do
- Do not code.
- Do not debug.
- Do not finish or merge a branch.
- Do not replace a plan with vague prose.

## Done Probe
- `subject.md` has scope, milestones, tasks, and verification.
- Each task is concrete enough to execute.
- Risks or open questions are recorded.

## Failure Condition
- Design input is still unclear.
- Tasks are not actionable.
- Verification is missing.

## Abnormal Exit Hint
- Key constraints are missing.
- The design is still disputed.
- The work is too large to plan coherently in one pass.

## Record Target
- `docs/orbits/sp-plan/subject.md`

## Record Minimum
- scope
- milestones
- tasks
- verification
- risks
- handoff
